
# Анализ опасных мест при миграции миграции


1. Инфраструктура (оборудование и сеть)

- Проблема: Локальный физический сервер в здании офиса может являться единой точкой отказа (SPOF). На нем развернуто слишком много несовместимых ролей (AD, Exchange, файловая помойка, 1С). Локальная сеть может быть не готова к микросервисной архитектуре, где количество сетевых запросов (межсервисного взаимодействия) возрастает в сотни раз по сравнению с монолитом.
- Риск: Критическое снижение производительности из-за сетевых задержек (Network Latency), риск физической потери данных (пожар/затопление или иное физическое бедствие в офисе).

2. Программное обеспечение и данные (ПО)

- Проблема: Файловый режим "1С" и хранение медицинских карт/анализов в неструктурированных файлах (Excel, JPG, PDF) на общем диске. Отсутствие СУБД. Данные фрагментированы, дублируются и не имеют четких схем валидации.
- Риск: Блокировки таблиц при росте штата (в файловом режиме 1С), невозможность распараллелить микросервисы (все упрется в единый сетевой диск), деградация дисковой подсистемы IOPS.

3. Интеграция и связи

- Проблема: Взаимодействие через устаревшие технологии, полное отсутствие шифрования внутренних потоков данных и контроля контрактов. Новые микросервисы не смогут бесшовно общаться со старой «1С» без слоя абстракции.
- Риск: Отказ кассовых аппаратов, невозможность интеграции внешней лаборатории анализов без переписывания бэкенда, неконтролируемые утечки данных между контурами.

4. Процессы и безопасность

- Проблема: Ручной ввод расширенных анкет пациентов сотрудниками ресепшена, отсутствие какого-либо аудита действий и логов чтения конфиденциальных данных. Авторизация ограничена только доменной учеткой Windows.
- Риск: Инсайдерские утечки (сотрудник может скопировать файлы Excel), невозможность расследования инцидентов ИБ, человеческий фактор при занесении медицинских тегов.


# Рекомендации по устранению

Меры по снижению рисков производительности и конфиденциальности при переходе на целевую микросервисную архитектуру To-Be разделены по приоритетам.

Приоритет 1: Критический - выполняется до начала миграции

1. Миграция 1С с файлового режима на клиент-серверный: Перевести базы «1С:Бухгалтерия» и «Торговля и склад» на выделенную реляционную СУБД (например, PostgreSQL) с оптимизацией индексов. Это устранит жесткие блокировки таблиц при конкурентном доступе микросервисов.
2. Развертывание реляционной СУБД для новых сервисов: Полностью отказаться от хранения PII-данных пациентов в Excel-файлах локальной сети. Спроектировать центральную реляционную БД под управлением современной СУБД с транзакционной целостностью (ACID).
3. Внедрение шифрования и TLS во внутреннем контуре: Запретить передачу данных в открытом виде по локальной сети. Настроить mTLS (расширение TLS) для связи между новыми сервисами (Портал, CRM, API Gateway).

Для реализации использовать Parallel Run с последующим использованием Branch by Abstraction для отдельных компонентов.

Приоритет 2: Высокий - выполняется в процессе разработки MVP

1. Перенос инфраструктуры в защищенное гибридное облако: Разместить контейнеры микросервисов и базы данных в аттестованном облачном контуре (соответствующем требованиям ИБ для медицинских данных), оставив локальный сервер только как контроллер домена Active Directory и DHCP. Это решит проблему масштабируемости бизнеса и защитит от единой точки отказа (SPOF).
2. Внедрение централизованного логирования аудита доступов: Подключить сквозное логирование (аудит-трейл) к шине данных. Любое чтение или модификация медицинской карты пациента должны фиксироваться в неизменяемом логе с указанием ID сотрудника ресепшена или врача.

Приоритет 3: Средний - финальное состояние и автоматизация

1. Создание пайплайна миграции Excel -> Data Lake (ETL): Разработать автоматизированные скрипты миграции исторических данных из файлов Excel/PDF, включающие обязательную деидентификацию (маскирование и токенизацию) конфиденциальных полей на лету перед загрузкой в озеро данных для ML/BI.
2. Постепенно перевести кассовые терминалы и периферийное оборудование на легковесные асинхронные микросервисные контракты.
