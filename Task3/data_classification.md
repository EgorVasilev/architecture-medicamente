| Данные | В чем необходимость защиты | Инструменты защиты |
| :--- | :--- | :--- |
| **Прямые PII пациентов**<br>*(Ф. И. О., дата рождения, телефон, электронная почта, адресе прописки, место работы или учёбы, хронические заболевания)*<br><br>• *Состояние:* Хранение и Передача<br>• *Риск:* Высокий (кража личности, нарушение ФЗ-152) | **Критически важны для идентификации.** Утечка приводит к крупным штрафам регуляторов, потере лицензии и репутационному краху. Требуется обеспечение "Права на забвение" (полное каскадное удаление по запросу клиента). | **В движении:** TLS 1.3 с жесткими шифрами (PFS).<br><br>**В хранении:** Процедура токенизации, например, через *HashiCorp Vault* (ФИО заменяется на `Token_ID`). Симметричное шифрование AES-256.<br><br>**На экранах:** Динамическое маскирование на API Gateway (ресепшен видит только `Ив**** И.И.` и `+7(999)***-12-34`). |
| **Медицинские данные**<br>*(Анализы, диагнозы, заключения врачей, назначения)*<br><br>• *Состояние:* Хранение, передача и использование<br>• *Риск:* Критический (Шантаж пациентов, утечка врачебной тайны) | **Особая категория персональных данных.** Самая чувствительная зона компании. Пациент должен видеть только свои анализы (защита от IDOR на API-контрактах). Сотрудники ресепшена вообще не должны иметь доступа к медицинскому контенту, только к метаданным записи. | **Доступ (ABAC):** Контроль через *Open Policy Agent*. Правило (пример): `Доступ разрешен, если User.Role == Doctor И Doctor.ID == Patient.AssignedDoctor`.<br><br>**В хранении:** Шифрование на уровне столбцов БД (Column-level encryption) отдельными ключами.<br><br>**Аудит:** Неизменяемый лог (*Immutable Audit Trail*) на любое чтение мед. данных с немедленным алертингом при массовых запросах. |
| **Данные записи и расписания**<br>*(Дата/время приема, ФИО врача, статус подтверждения)*<br><br>• *Состояние:* Передача и использование<br>• *Риск:* Средний (Раскрытие паттернов поведения клиентов) | **Основа MVP и автоматизации процессов.** Необходимы для координации ресепшена, отправки пушей и работы голосового робота. Риск заключается в возможности третьих лиц узнать, к какому именно специалисту (например, к психиатру или онкологу) ходит конкретный человек. | **Доступ (RBAC):** Ресепшен имеет доступ `Read/Write` через CRM, но без доступа к истории прошлых болезней.<br><br>**Внешние каналы:** Голосовой робот и партнеры получают минимизированные JSON-контракты через API Gateway: передается только `UUID_записи`, `Дата_Время` и `ID_Врача` (без ФИО пациента). |
| **Платежные данные**<br>*(Токены карт, история транзакций, суммы, договоры)*<br><br>• *Состояние:* Передача и хранение<br>• *Риск:* Высокий (Финансовое мошенничество) | **Автоматизация оплаты через платежный шлюз.** Требуется строгое соответствие стандарту PCI DSS. Медикаменте не должна хранить сырые CVC/CVV коды и полные номера карт на своей стороне, чтобы избежать финансовых краж при компрометации CRM. | **Изоляция:** Перенос обработки на выделенный изолированный компонент `Платёжный шлюз`.<br><br>**Защита:** Использование внешней банковской токенизации (в БД CRM сохраняется только маскированный номер `4111****1111` и `Transaction_ID`). Передача данных по строго выделенным зашифрованным VPN/TLS-каналам. |
| **Аналитические данные (Excel, BI)**<br>*(Датасеты для BI, ML-моделей, обучения AI/LLM)*<br><br>• *Состояние:* Использование (Data-in-Use) и хранение в Data Lake<br>• *Риск:* Средний (Деанонимизация через перекрестный анализ) | **Необходимы для развития бизнеса, обучения AI и автоматизации.** Исходные Excel-файлы содержат хаотичные PII. Перенос в Озеро данных требует полной очистки, чтобы аналитики и ML-модели не имели физического доступа к реальным именам и картам пациентов. | **Пайплайн деидентификации (ETL):** Автоматическое удаление ФИО/паспортов при переносе из Excel в Data Lake.<br><br>**Технологии:** Необратимое хэширование (SHA-256 + соль) для связывания анализов, маскирование дат (перевод дат в возрастные группы, например: 34 года -> группа `30-35`).<br><br>**Конфигурируемость:** Настройки маскирования колонок вынесены в YAML-конфигурации пайплайна без изменения кода. |
